Troubleshooting

What the common failures look like in this project and how to fix them.

SymptomUsual causeWhat to do
Backend crashes at start: ValueError: invalid literal for int() ... 'tcp://10.96...:6379'Kubernetes injects <SERVICE>_PORT=tcp://ip:port for every Service. An old image reads REDIS_PORT and gets that stringRebuild the image from the current app/backend (it uses CACHE_PORT), load it, restart the Deployment. Quick workaround: enableServiceLinks: false in the pod spec
kind: command not found (or kubectl, docker)Not installed, or its folder is not on the PATH, or the terminal was opened before you changed the PATHFollow Act 0.1; open a new terminal; check with which kind or Get-Command kind
Cannot connect to the Docker daemon or a Docker pipe errorDocker Desktop (or the Docker service) is not runningStart it, wait until it reports running, then retry
kubectl version --client shows an old versionDocker Desktop's bundled kubectl comes first in the PATHPut your own tools folder before it in the PATH, or remove Docker's copy
ImagePullBackOff or ErrImagePull on poll-*The image exists only in your local Docker, not inside the clusterkind load docker-image <image> --name poll after every build
Frontend CrashLoopBackOff, log says host not found in upstream "backend"The backend Service does not exist yet. nginx resolves it at startCreate the backend Service first; the pod recovers on its next restart
Backend pods Running but 0/1, /ready says waiting_for: databaseThe tables do not exist, or Postgres is not readyRun the migration Job; check kubectl get pods for postgres-0
Postgres crashes with directory exists but is not empty or mentions lost+foundThe data directory is the volume's rootSet PGDATA to a sub-folder such as /var/lib/postgresql/data/pgdata
PVC stays PendingThe storage class waits for a pod that uses the volumeNormal until the pod is scheduled. If the pod is Pending too, kubectl describe pod
HPA shows <unknown>/50%metrics-server is not ready, or the pods have no CPU requestkubectl top pods; check the add-on and the --kubelet-insecure-tls patch; add a CPU request
HPA never scales upThe load is too small for the CPU requestRun more workers in load.sh, or raise CPU_COST_MS and restart the backend
localhost:8080 refuses the connectionNo port mapping, ingress controller not ready, or port 8080 already in useCheck the kind config mapping, kubectl get pods -n ingress-nginx; free the port or change hostPort
localhost:8080 returns 404 from nginxThe Ingress is missing or has the wrong classkubectl get ingress; use ingressClassName: nginx
The page shows 502 or Cannot load resultsThe backend has no ready podskubectl get pods -l app=backend and kubectl get endpoints backend
Pods turn NotReady after applying network policiesProbe traffic from the node may be blocked by your network plugin's policy implementationkubectl describe pod shows probe failures. Delete default-deny-ingress to confirm, then check your CNI's documentation on host traffic
A policy has no effect at allThe network plugin does not enforce NetworkPolicyUse a cluster whose CNI enforces policies, then repeat the timeout check
kubectl drain keeps retryingA PodDisruptionBudget would be violatedWait for replacement pods to be Ready, or check kubectl get pdb
A node stays SchedulingDisabledA drain cordons the node and does not undo itkubectl uncordon <node>
Change to a ConfigMap has no effectEnvironment variables are read once at pod startkubectl rollout restart deploy/backend
kubectl apply brought back an old imageA manual set image or rollout undo changed the cluster but not your fileEdit the file to the version you want, then apply
load.sh is slow or fails on WindowsProcess start-up is slow in some shellsUse WSL or Git Bash, and fewer workers

Useful commands

kubectl get pods -o wide                     # where, which IP
kubectl describe pod NAME                    # events at the bottom
kubectl logs NAME --previous                 # the log of the crashed container
kubectl get events --sort-by=.lastTimestamp
kubectl get endpoints backend                # which pods receive traffic
kubectl exec deploy/backend -- printenv      # what the container actually sees
kubectl rollout history deploy/backend
kubectl auth can-i VERB RESOURCE --as=system:serviceaccount:poll:NAME

Clean up

kind delete cluster --name poll
